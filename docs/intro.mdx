envy is an **unopinionated**, **hermetic**, **per-project**, **serverless**
package manager — unless you want it to be otherwise.

- **Unopinionated.** envy has zero opinion about what a package *is*. A
  compiler toolchain, a vendor SDK, a Python interpreter, a Homebrew formula, a
  udev rule — anything you can describe with a handful of Lua verbs is a
  package.
- **Hermetic.** A project pins its entire toolchain — including envy itself, by
  version and checksum — in one `envy.lua` manifest checked into the repo. Clone
  the repo, run the committed bootstrap script, and you have the exact tools the
  project expects. No Homebrew, no apt, no "install these ten things first."
- **Per-project.** Every project declares its own world. Installed packages
  live in a user-wide content-addressed cache shared across projects, so ten
  projects pinning the same compiler store it once.
- **Serverless.** There is no registry, no daemon, no central server. Package
  specs fetch bits from wherever they already live — HTTPS, git, S3, local
  files — verify them, and install them.

…*unless you want it to be otherwise*: an optional [package
depot](/concepts/depots) lets your CI publish prebuilt package artifacts that
everyone else's `envy sync` pulls instead of building from source. It's an
accelerator you can bolt on, never a requirement.
