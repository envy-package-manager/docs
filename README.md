# envy docs

Source for the envy documentation site. [Docusaurus 3.10][docusaurus], built to
static HTML and published to GitHub Pages by CI.

Live at <https://envy-package-manager.github.io/docs/>.

> The pages in `docs/` are **placeholder content** derived from the envy
> sources. Replace them with real docs before announcing the site.

## Requirements

Node >= 20 and npm. Nothing else — no Ruby, no Python, no global installs.

## Local development

```bash
npm install        # once
npm start          # dev server at http://localhost:3000, hot reload
npm run build      # production build into build/
npm run serve      # serve build/ locally, exactly as published
npm run typecheck  # tsc over the config, sidebars, and any TSX
npm run clear      # nuke .docusaurus/ and build/ when the cache misbehaves
```

`npm run build` is also the link checker: `onBrokenLinks`, `onBrokenAnchors`,
and the markdown link/image hooks are all set to `throw` in
`docusaurus.config.ts`. A dead link fails the build, and therefore CI.

## Layout

| Path                     | What lives there                                    |
| ------------------------ | --------------------------------------------------- |
| `docs/`                  | All page content, as Markdown/MDX.                   |
| `sidebars.ts`            | Sidebar definition. Currently autogenerated from `docs/`. |
| `docusaurus.config.ts`   | Site config: URL, navbar, footer, plugins, syntax highlighting. |
| `src/css/custom.css`     | Global styles. Infima variable overrides.            |
| `static/`                | Copied verbatim to the site root. Images, `.nojekyll`. |
| `.github/workflows/`     | CI and publish.                                      |

There is no `src/pages/`. `routeBasePath` is `/`, so `docs/intro.mdx` (which sets
`slug: /`) *is* the home page. To add a separate marketing landing page, set
`routeBasePath: '/docs'`, drop `slug: /` from `intro.mdx`, and add
`src/pages/index.tsx`.

The splash block at the top of `intro.mdx` is plain MDX plus the `.hero-splash*`
rules in `custom.css`; no swizzled theme components are involved. It sets
`hide_title: true` because the docs plugin only recognizes a Markdown `#`
heading as the page title and would otherwise inject a second `<h1>` above it.

## Adding a page

Drop a `.md` or `.mdx` file in `docs/` with front matter:

```markdown
---
sidebar_position: 6
title: Whatever
---
```

The sidebar is autogenerated from the directory tree, ordered by
`sidebar_position`. For a nested section, make a subdirectory and add a
`_category_.json`:

```json
{"label": "Guides", "position": 4, "link": {"type": "generated-index"}}
```

Once the tree outgrows that, replace the `autogenerated` entry in `sidebars.ts`
with an explicit list.

## Style and layout rules

- **Colors come from Infima variables in `src/css/custom.css`.** The palette is
  derived from the mascot's green (`#9f0`): a darkened ramp for light mode, a
  brightened one for dark. Do not hardcode colors in components or MDX — add a
  variable.
- **Prose matches the envy house style**: terse, pithy, high information density.
  Short declarative sentences. Examples demonstrate several concepts at once.
- **Code blocks get a language and, where useful, a title**:
  ````
  ```lua title="envy.lua"
  ````
  Languages beyond the defaults must be listed in `themeConfig.prism.additionalLanguages`.
  `lua`, `bash`, `powershell`, `json`, and `makefile` are already registered.
- **Cross-link with relative file paths** (`./concepts.md`), not URLs. The build
  validates them.
- **Artwork lives in `static/img/`.** `Ruckus.svg` (navbar logo) and `Ruckus.png`
  (favicon source, Open Graph card) are copied from the envy repo's `artwork/`.
  The Open Graph card is a placeholder — replace it with a purpose-built
  1200x630 image.

## CI

Pull requests run `.github/workflows/ci.yml`: typecheck, then build.

The workflow ends in a job named **`all-checks-pass`**, which depends on every
other job. **That name is frozen and is the only required status check in branch
protection.** Add or rename jobs freely — just add them to that job's `needs`
list — and the GitHub-side config never has to change. Old commits stay
mergeable too, since the check existed under the same name back then.

It is guarded with `if: always()` and asserts on `needs.*.result`. Without that,
a failed dependency would leave the gate *skipped*, and GitHub counts a skipped
required check as satisfied. `skipped` is treated as failure.

One caveat: never add path filters to this workflow. If it doesn't run, the
required check never reports and PRs block forever.

## Publishing

Push to `main` → `.github/workflows/deploy.yml` builds and deploys.

**One-time repo setup:** Settings → Pages → Source → **GitHub Actions**. Without
that, the deploy job fails.

Do not use `npm run deploy` (Docusaurus's `gh-pages` push). This site publishes
via the Pages artifact API; the two approaches conflict.

### Changing the URL

`url` and `baseUrl` in `docusaurus.config.ts` must match where the site is
actually served, or every asset 404s.

| Target                                    | `url`                                     | `baseUrl`  |
| ----------------------------------------- | ----------------------------------------- | ---------- |
| Current: project page under the `docs` repo | `https://envy-package-manager.github.io` | `/docs/`   |
| Org root site (repo renamed `envy-package-manager.github.io`) | same | `/`        |
| Custom domain                             | `https://envy.example`                    | `/`        |

For a custom domain, also add `static/CNAME` containing the bare hostname.
